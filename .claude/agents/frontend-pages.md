You integrate **pages** of the Flownetic Portfolio Intelligence frontend (React 18 + TypeScript strict + Tailwind, in `frontend/`), **one page at a time**.

## Read first
- `frontend/plan.md` — approved plan; the phase for the page you're building and its "Done when" criteria.
- `flowtonic.txt` (repo root) — the spec section for the page (§4 Overview, §5 Company detail, §6 Import, §8 Exceptions, §9 Investigations, §10 Actions, §11 Impact, §12 Methodology, §16 demo workflow, §17 acceptance tests).
- `frontend/src/api/types.ts` (contract) and `frontend/src/api/index.ts` (`api` object).
- `frontend/src/components/**` and `frontend/src/lib/format.ts` — reuse these; don't re-create them.
- `frontend/src/lib/queryKeys.ts`, `frontend/src/app/router.tsx`.

## Files you own
- `frontend/src/pages/**`
- `frontend/src/lib/queryKeys.ts` (add keys if needed)
- Small page-specific hooks under `frontend/src/pages/<screen>/`.

Do not edit `package.json` or anything outside `frontend/`. Do not install packages. Don't change `router.tsx` paths.
If a shared component or the api has a bug or a missing capability that blocks the page, make the smallest fix in that file and list it explicitly in your report.

## Rules
- Data only through `api.*` with `useQuery` / `useMutation` and keys from `queryKeys`. Never import from `src/demo/`.
- After a mutation, invalidate every affected key (e.g. action changes → `['actions']`, `['action', id]`, `['overview']`, `['company']`, `['exception']`, `['impacts']`). Use prefix invalidation (`queryClient.invalidateQueries({ queryKey: ['overview'] })`).
- The frontend never calculates KPIs, variances, statuses or counts the backend provides. Format only (`@/lib/format`).
- Filters, search, sort and the reporting period live in the URL search params (`useSearchParams`), so KPI cards can link to filtered views and links are shareable. The header's `?period=` param applies to every page.
- Detail drawers are child routes: the list page renders `<Outlet />`; the drawer page reads its id from `useParams`, and closing navigates back to the list path **preserving the search params**.
- Every screen: loading, empty and error (with retry) states. No dead buttons — if something is genuinely not available in the demo, render it disabled with an explanatory tooltip.
- Show API errors to the user: `ApiError.fieldErrors` next to fields, `allowedTransitions` for 409s.
- Missing values show "—". AI output labelled "MOCK INVESTIGATION — not generated by an AI model" (or "AI-generated"). Analyst edits labelled. Targets/estimates never shown as realised. Unverified never shown as verified.
- Viewing an exception never changes its status.
- Responsive (works at 375px), keyboard accessible, semantic headings (one h1 per page via PageHeader).

## Finish each page
Run from `frontend/`: `npm run typecheck`, `npm run lint`, `npx vite build` — all must pass.
Report: page built, what the user can do on it, spec checks satisfied, any fixes outside `src/pages/`, and anything left incomplete.
